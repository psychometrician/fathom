## Why this one, and why it is deliberately unexciting

**The counter is at 0 of 3 and `61af6458…` has described exactly one unseen
document.** The gate needs quiet files, and a quiet file is only evidence if it
was chosen without regard to what the probe is good at.

Chosen because **a container registry's catalogue is not a kind the corpus
has**, and because it is regular in a way most of the corpus is not: 100 objects
of one type, written by one producer, with a small nested array each. **If the
probe has stopped moving, this is the sort of document that will say so.**

> **Deliberately paired against file 21.** That one was 1,000 heterogeneous
> records from thousands of publishers and it found a defect. This one is 100
> homogeneous records from a single machine. **Two ordinary documents at opposite
> ends of the regularity range, back to back, is a better test of convergence
> than two of the same kind** — and if a 100-record uniform document still finds
> something, that is worth more than the quiet result I expect.

**It is small on purpose and that is a stated limitation.** One API page is a
few hundred KB, so this file cannot say anything about scale. `14-nyc-311`,
`20-homebrew-formulae` and `04-gharchive` own that question; this one is about
whether the description holds still.

## Grading

**Graded in all thirteen tools on 2026-08-11.** The probe was not run and not
unfrozen. **This entry is the corpus's NESTED CONTROL** — one key-set per shape,
no keys-as-data, no polymorphism, no split, and a one-to-many child — and its
value is what it makes the OTHER entries' findings say.

### 1. The finding is about the probe, not the tools: three states of empty

| image field | state | count |
|---|---|---|
| `os_version` | **null** | 1,360 of 1,388 |
| `variant` | **null** | 1,125 |
| `features` | **empty string** | 1,388 |
| `os_features` | **empty string** | 1,388 |

**The probe's `16% empty` on the images table is exactly the nulls** —
(1,360 + 1,125) / (1,388 x 11). The **2,776 empty strings count as FILLED**.
That is a defensible choice and it is a choice, and this is the first corpus
document where it moves the headline: counting them too gives **34%**.

**ijson, rrapply's melt, purrr, jq, jqr and DuckDB can each report all three
states separately.** pandas and polars keep `""` apart from null only by
accident of dtype, and `isna()`/`null_count()` see only the null. **No tool
volunteers the distinction and the probe does not name it.**

### 3. `bind`'s mechanism, finally pinned by a document simple enough to see it

Sixth point, and the first that is **narrow and dense**: **100 x 213 at 21.8% NA**.

> 16 tag fields + (the widest tag's **18** images x 11 image fields) = **214**,
> and `bind` produced **213**. **It spends a column per (POSITION, FIELD) pair**,
> so the width is set by the LONGEST CHILD ARRAY and not by key raggedness.
> That is why entry 18's 100 records gave 37,006 columns and this document's 100
> give 213. **And the columns are POSITIONS — question 7a's property — which is
> the same price entry 14 paid for the corpus's only list-column-free extract.
> A dense `bind` and a positional `bind` are the same thing.**

## The fourteenth tool, 2026-08-11 — `try-tidyr.R`

**This entry's flagged question is measured: the null/empty-string distinction
is a per-FIELD convention, not a per-cell judgement.**

Over the images table's **16,656 scalar cells**:

| | | |
|---|---|---|
| NA (a JSON null) | **2,485** | 14.9% |
| empty string `""` | **2,776** | 16.7% |
| either | **5,261** | 31.6% |

**And not one of the twelve fields uses both:**

| | null | empty |
|---|---|---|
| `features` | 0 | **1,388 of 1,388** |
| `os_features` | 0 | **1,388 of 1,388** |
| `variant` | **1,125** | 0 |
| `os_version` | **1,360** | 0 |

> **Two fields say *nothing here* one way and two say it the other,
> consistently, because they come from different writers.** Folding the two into
> one emptiness figure hides which convention a field follows — **and the
> convention is the only thing that tells you whether an empty string is a value
> or a hole.** That is an argument for reporting them separately, and it is
> offered as evidence rather than as a decision.

**tidyr belongs with the tools that CAN separate the three states**, not with
pandas and polars, which keep `""` apart from null only by accident of dtype. It
still **volunteers** neither.

**And it is the contrast that pins `bind`'s cost.** jsonlite's `bind` is
**100 x 213** — a column per (position, field) pair, so the width is set by the
longest child array. tidyr's `unnest_longer` gives **1,388 x 12** for the same
data: **the same information as ROWS instead of COLUMNS**, and the width stops
depending on the deepest tag. Both row shapes are one call each and **neither is
priced**.

Every tag has at least one image, so `unnest_longer`'s lossy default is safe
here — **the only document of the fourteen where it is.**
